## Zwei Phasen, eine Codebasis

Das Ziel: für eine Cloud-Zielumgebung bauen, ohne während der Entwicklung für die Cloud zu zahlen. Phase 1 läuft auf einem Raspberry Pi 5 mit Docker Compose, einer kostenlosen Neon-Postgres-Datenbank in Frankfurt und privatem Zugriff über Tailscale. Phase 2 bringt denselben Code auf Lambda, SQS, EventBridge Scheduler, S3 und CloudFront, definiert mit Terraform und ausgeliefert über GitHub OIDC. Pi und Lambda sind beide arm64, daher genügt ein Build-Ziel.

## Vier Ports, alles andere gemeinsam

Nur vier Dinge unterscheiden sich wirklich zwischen Pi und AWS. Jedes ist eine kleine Schnittstelle mit einer Implementierung pro Umgebung. Die Geschäftslogik hängt nur von den Schnittstellen ab, umgebungsspezifischer Code steckt daher ausschließlich in Einstiegspunkten und Adaptern.

| Aufgabe | Raspberry Pi | AWS |
| --- | --- | --- |
| Queue | ElasticMQ | SQS |
| Zeitpläne | Cron in einem Container | EventBridge Scheduler |
| Token-Verschlüsselung | lokale AES-GCM-Schlüsseldatei | KMS |
| Ausgehende E-Mail | keine | SES |

Die Queue-Handler sind einfache Funktionen, die einen Batch annehmen und die IDs fehlgeschlagener Nachrichten zurückgeben, also die Form der Lambda-Partial-Batch-Antwort. Auf dem Pi ruft ein Poller sie auf, auf AWS die Lambda-Laufzeit. Der Pi-Adapter ist das AWS SDK, das auf ElasticMQ zeigt; der Pi übt damit bereits den echten Client-Code.

## Isolation durch die Datenbank

In diesem System liegen Namen von Recruitern und E-Mail-Metadaten anderer Menschen. Ein vergessener Filter im Anwendungscode darf daher keine Zeilen eines Mandanten preisgeben. Row-Level Security in Postgres erzwingt die Grenze: eine Policy pro Mandantentabelle, erzwungen und fail-closed, wenn kein Mandant gesetzt ist. Zwei Anwendungsrollen können sie nicht umgehen. Die Rollen entstehen in SQL-Migrationen, nie in einer Cloud-Konsole, weil eine dort angelegte Rolle unbemerkt eine Umgehung erbt und jede Policy wirkungslos wird. Jeder Serverprozess verweigert außerdem den Start, wenn seine Datenbankrolle Superuser ist, Row-Level Security umgeht oder Tabellen besitzt.

<TradeOff

  price="Row-Level Security schützt nicht vor SQL-Injection, und das Migrationswerkzeug kann die erzwungenen Policies nicht ausdrücken, daher braucht jede Mandantentabelle eine handgeschriebene Folgemigration."

## Eine Pipeline, die sich nicht durch Überspringen bestehen lässt

Die CI läuft gegen echte Postgres- und ElasticMQ-Container, nicht gegen Mocks. Die Datenbank- und Queue-Tests werden still übersprungen, wenn diese Dienste fehlen, ein grüner Lauf hätte also nichts bedeuten können. Die Pipeline lässt den Build jetzt scheitern, sobald ein Test als übersprungen gemeldet wird. Die Pi-Laufzeit härtet jeden dauerhaft laufenden Container: schreibgeschütztes Root-Dateisystem, alle Capabilities entfernt, rotierte Logs. Nur ein einmaliger Migrations-Container sieht je die Zugangsdaten des Datenbank-Eigentümers.
