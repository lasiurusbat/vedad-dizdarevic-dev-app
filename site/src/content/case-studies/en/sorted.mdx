## Scope

Sorted is live at [sorted.onl](https://sorted.onl), with self sign-up, Stripe billing and custom plans for support teams. I own the platform end to end: the infrastructure, the pipelines and the operations, plus the application they run. I built it from September 17 to October 31, 2026. This page describes the production configuration as defined in Terraform. The running costs are projected from my AWS bill, the Multi-AZ figures are estimates from the docs in the repository, and failover has been designed but not drilled.

## Architecture

Two paths run through the platform:

- **Requests:** browser → Cloudflare → ALB with an ACM certificate → nginx and the Bun server in one Fargate task → RDS PostgreSQL in private subnets.
- **Mail:** customer email → SES receipt rule → S3 (own KMS key) and SNS → signed webhook on the ALB → saved ticket → `pg-boss` job for AI classification → agent queue or automatic reply through SES. Delivery events come back through SNS.

## Compute, network and data

- **Compute.** One Fargate task with two containers, nginx and the Bun server, on ARM64 for about 20% lower cost.
- **Network.** Security groups reference each other, not CIDRs. RDS accepts connections only from the task. There is no SSH and no bastion; ECS Exec is the break-glass path.
- **Data.** Private RDS with encryption, a staged rollout of database TLS (`off`, `verify`, `require`) and secrets injected from Secrets Manager. Backups of the documentation and subscriber lists go straight to S3 Glacier Deep Archive, in a versioned bucket with its own KMS key.
- **Mail and attachments.** SES, SNS and S3 form the inbound pipeline. Webhooks trust only SNS signatures, the inbound bucket has its own KMS key, and GuardDuty Malware Protection scans every attachment.

## Release path

Two repositories, two roles, no stored keys. In the application repository, a git tag runs the full check suite and pushes an immutable image to ECR. The infrastructure repository decides which image runs: a deploy is a reviewed Terraform change, and the workflow writes the plan into the run summary and applies that exact saved plan. Infrastructure CI runs `terraform fmt`, `validate` and 22 offline `terraform test` runs with mocked providers, which assert the security properties without an AWS account.

## Monitoring

CloudWatch holds the data; Grafana Cloud reads it in place, so nothing is shipped or copied. Terraform creates a read-only IAM role that Grafana's AWS account can assume only with the stack's External ID (protection against the confused deputy), limited to CloudWatch metrics and that environment's log group.

- **Logs.** Containers log to `/ecs/sorted-<env>` in CloudWatch Logs, 30 days in prod and 7 in dev. The server writes structured JSON with a request ID, so one Logs Insights query follows a user's `X-Request-Id` through the system.
- **Metrics.** The AWS namespaces for the ALB, ECS, RDS and SES, plus Container Insights in prod for the running task count.
- **Uptime.** Synthetic checks probe the site and `/api/health`, which also checks the database.
- **Spot visibility.** An EventBridge rule writes every `SpotInterruption` task stop into its own log group, so any restart is explainable.
- **Alerts and runbook.** Rules on the same signals as the dashboard, each mapped to a section of a symptom-first runbook: the first five minutes, rollback, and the failure modes I actually hit.

## The workload

The platform exists to run this application. Each team gets a Sorted address, or forwards its existing one. An incoming email becomes a ticket. AI classifies it, summarizes it and, for non-transactional questions, answers from the team's knowledge base. Agents assign, reply and merge from one queue, with templates and an audit log. Teams have three roles, the interface comes in 22 languages, and there is a super-admin console.

Four rules keep the AI safe:

1. **Refund and payment tickets never go to the AI.**
2. **The webhook never calls the AI.** It saves the message and returns 200, so AI latency or failure cannot lose a customer's email.
3. **Guardrails live in code.** The model returns category, priority, confidence and a draft. Application code decides whether anything is sent.
4. **Every AI failure ends with the ticket open for a human.** A sweep every five minutes opens anything a crash left behind.

## Limitations and what I would do next

- **One task.** The database fails over across zones, but the single app task is restarted by ECS in the other zone, a short interruption. I have not tested it under load or a real failover, and there is no autoscaling yet.
- **The deploy role is an administrator.** This is a deliberate trade-off with tight trust conditions. A permission boundary and a scoped policy generated from a plan would be a better end state.
- **Alert rules live in Grafana, not in Terraform.** Only the IAM role is code today.
- **Terraform state holds generated secrets in plain text.** The bucket is private and encrypted, but I would create those secrets outside state or rotate them on a schedule.
- **Backup restore is documented but not drilled.** Both the RDS snapshot and the Deep Archive backups need a scheduled restore test.
- **No WAF rules of my own.** I would add rate-based rules and test them against the SES and Stripe webhooks first, because a challenge on those paths would silently break mail and billing.

I do not claim a formal security audit. I used review passes while building.
