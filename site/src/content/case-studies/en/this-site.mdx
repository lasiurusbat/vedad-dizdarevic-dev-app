## Architecture

Three paths run through the site: requests, deploys, and the planned contact form with its alarms. The buttons above the diagram trace each one. ## A private bucket behind a Worker

<TradeOff
  gained="The bucket is never public, traffic is HTTPS from the browser to S3, and the edge logic is versioned, tested code."
  price="The Worker cannot use OIDC to reach AWS, so it holds the one long-lived access key in the setup. I rotate it by hand every 90 days."
/>

A public S3 website endpoint speaks plain HTTP to its origin, and CloudFront would put a second CDN behind Cloudflare. A Worker runs the edge logic on Cloudflare's free plan.

- **Signed reads.** The Worker signs every request to the S3 REST endpoint with SigV4 and retries once. The library default of ten retries with backoff could stall a page for seconds.
- **Read-only, and nothing to list.** Its IAM user has two permissions: read objects, and invoke the contact function. Without `s3:ListBucket`, nobody can list what the bucket holds. S3 answers a missing page with a 403, and the Worker serves the site's 404 page for it.
- **Clean URLs.** `/projects/sorted/` maps to its `index.html`; `/foo` redirects to `/foo/` only when that page exists.
- **Two caches.** Hashed assets are cached for a year as immutable; HTML stays at the edge for five minutes and is purged on every deploy.
- **The bucket itself.** Block Public Access on, a policy that denies any request without TLS, versioning with old versions expiring after 30 days, and server-side encryption.

## Security headers in one place

<TradeOff
  gained="One source for every header, tested in the Worker's unit tests and again on the live domain after each deploy."
  price="A strict policy rules out inline scripts and styles. The theme script, the diagrams and every dynamic size on the site had to be built without them."
/>

Only the Worker sets headers; neither the Cloudflare dashboard nor the framework adds any. Every response carries six: a Content Security Policy, HSTS with preload, `X-Frame-Options: DENY`, `nosniff`, a referrer policy and a permissions policy.

- **No `'unsafe-inline'`.** Styles and scripts come from the site's own origin. The build writes no inline styles, and an e2e test counts `style` attributes.
- **Diagrams under the production policy.** Framework islands emit inline scripts, so the diagrams mount through a plain module script when they scroll into view. A test loads them with the production CSP and fails on any violation.
- **Report-only first.** The policy ships in report-only mode until every page is clean in the browser console; enforcing it is a one-line change.

## No stored keys in CI

<TradeOff
  gained="Each workflow run gets AWS credentials that expire with the job, and GitHub stores no AWS secret that could leak."
  price="The trust policies pin numeric GitHub IDs, so renaming or recreating a repository means updating the bootstrap variables first."
/>

GitHub Actions assumes AWS roles through OIDC. A small bootstrap stack, applied once by hand, creates the Terraform state bucket and three roles:

- **`gh-app-deploy`** for the app repository's `main` branch. It can list, write and delete objects in the site bucket, nothing else, and cannot read the Terraform state.
- **`gh-infra-plan`** for pull requests in the infra repository: read-only, except for the state lock file.
- **`gh-infra-apply`** for `main` in the infra repository, in a protected `production` environment. It can change IAM only for names starting with `vdd-`, so it cannot edit the CI roles themselves.

GitHub now issues immutable subjects (`repo:<owner>@<ownerId>/<repo>@<repoId>`), so the roles trust the numeric owner and repository IDs. A new repository that reuses the name gets a new ID and no access.

## Two repositories, two pipelines

<TradeOff
  gained="Infrastructure and site change on their own schedules, each with its own scoped role and Cloudflare token."
  price="The values the app needs from Terraform, such as the bucket name and the role ARN, are copied into the app's Actions variables by hand."
/>

Terraform manages AWS and the Cloudflare zone, DNS and rules; Wrangler deploys the Worker script and its route. No resource is managed by both.

**App repository.** Every pull request runs lint and formatting, a type check and build, the Worker's tests in the Workers runtime, Playwright with axe in both themes and languages, and gitleaks. A push to `main` deploys:

1. Hashed assets go up first and nothing is deleted yet, so pages from the old build still find their files.
2. The rest goes up with `--delete`.
3. Wrangler deploys the Worker, and the cache is purged.
4. A smoke test checks the live domain: all six headers, the 404 page, `405` for a `POST`, `www` and `http` redirects, and that the bucket refuses direct access.

**Infra repository.** Every pull request runs `fmt`, `validate`, Trivy, Checkov and gitleaks, and posts the plan as a comment. A merge applies it in the protected environment, one run at a time. The apply refuses any plan that deletes or replaces a resource until a person re-runs it with `allow_destroy`. Scanner exceptions sit next to the code, each with a reason.

## Language without a cookie

<TradeOff
  gained="German-speaking visitors land on the German home page without a cookie, so the site needs no consent banner."
  price="Without memory, a visitor in Germany who opens the home page in a new tab later is sent to German again."
/>

The Worker sends a fresh visit to `/` from Germany, Austria, Switzerland, Luxembourg or Liechtenstein to `/de/` with an uncached `302`. It leaves deep links, clicks within the site and URLs with `?lang=` alone. The language switch links to `/?lang=en`, so a click on English always lands on English. Crawlers, which mostly come from the US, index the English home page.

## Costs and alarms on a shared account

<TradeOff
  gained="Cloudflare's free plan carries DNS, TLS, the edge cache and the Worker. On AWS the site only uses S3 today; Lambda and SES start when the form goes live."
  price="The AWS account is shared with Sorted, so the budget filters on a cost allocation tag that has to be activated by hand. If it is ever switched off, the budget reads $0 without a warning."
/>

- **A $5 monthly budget** with an alert at 100% of actual and of forecast spend, scoped to this project's `Project` tag.
- **CloudWatch alarms** on Lambda errors and throttles and on the SES bounce and complaint rates, sent through SNS to my inbox.
- **An uptime monitor** on the home page from outside AWS and Cloudflare.
- **Mail authentication.** SPF, DKIM for both the mailbox provider and SES, and DMARC with reports, all as Terraform-managed DNS records.

## The workload

The platform serves a static site built with Astro: English and German pages, case studies written in MDX against a typed schema, and Tailwind CSS. Pages without a diagram ship no framework JavaScript; the diagrams load React Flow only when they scroll into view. Fonts are self-hosted and there are no trackers.
